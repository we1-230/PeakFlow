## 零、一句话结论

一个跑在本地的 Spring Boot + Vue 秒杀商城，最终变成 **`https://peakflow.top`**
（阿里云美国弗吉尼亚 ECS，2核4G，单实例 6 容器，Let's Encrypt 证书）。
从"能跑"到"敢给别人看"，中间真正花时间的**不是写功能，而是三类事**：

1. **环境口径差异**（本地通、线上不通；localhost 通、容器内不通）
2. **契约不一致**（前端按臆想字段渲染、测试桩造假、数据库没有那个字段）
3. **判断被假象误导**（代理伪造 502、ICMP 通但 TCP 不通、healthy 但对外服务残缺）

这三类各踩了 8~10 个坑，下面逐个交代。

## 一、阶段一：本地（2026-10-15 ~ 10-16）

本地阶段的目标是"用 Docker 把整套栈跑起来，并且能一键回归"。
这一阶段最反直觉的一点：**本地环境本身就是一个坑源**，它和线上差异很大。

### 1.1 本地栈的形态

| 组件 | 本地端口 | 说明 |
|---|---|---|
| MySQL 8 | 3307 | 三套逻辑库 `peakflow_dev` / `_test` / `_prod` |
| Redis | 6380 | 三个逻辑库 db0/db1/db2 |
| RocketMQ | 9876 + 10911 | namesrv + broker |
| backend1 / backend2 | 8080 / 8081 | 双实例，验证负载均衡与分布式锁互斥 |
| tester | — | 含 JDK/Maven/newman/python3/redis-cli 的测试镜像 |

端口故意错开（3307/6380）是为了不和宿主机已有服务打架 —— 代价是**所有文档里的命令都得写对端口**，
这也是后来"照抄文档跑错库"的根源之一。

### 1.2 本地阶段真实踩到并修掉的坑

**坑：RocketMQ 容器 exit 253，而且 `docker logs` 一个字都没有**
镜像以 `rocketmq`（uid 3000）运行，但 Docker 新建的 named volume 是 `root:root 755`，
broker 写不进 store 目录就直接退出，**连日志文件都创建不了**。
定位手段不是看日志（没有日志），而是 `docker inspect` 看 `ExitCode` 和 `User`。
修法：移除 RocketMQ 的三个 named volume，只保留 `broker.conf:ro`（只读文件不受属主影响）。

**坑：nginx 容器永远 unhealthy，但 exec 进去手动 `wget` 又是通的**
healthcheck 里写的是 `http://localhost/healthz`，容器内 `localhost` 优先解析成 IPv6 `::1`，
而 nginx 只监听了 IPv4 `0.0.0.0:80`。修法：healthcheck 改成 `127.0.0.1`。
**这条极有代表性**：手动验证通、自动检查不通，说明问题不在服务本身，而在"探测方式"。

**坑：上传头像 4 个断言失败，业务码 3005**
`AliOssUtil` 无脑连 OSS，而本地没有 AccessKey → `InvalidCredentialsException`。
修法两层：代码层无凭证时降级写本地 `./uploads`；测试层把"必须是 aliyuncs.com"的断言
改成 `/(aliyuncs\.com|\/uploads\/)/`。

**坑：加了 `/uploads/**` 的静态映射，还是 403**
`SecurityConfig` 的白名单是**硬编码**的，不读 yml 里的 `security.white-list`。
两处白名单必须同步改（yml 那份是给 `JwtAuthenticationFilter` 用的）。

**坑：newman 上传用例报 "not a multipart request"**
newman 按**当前工作目录**解析集合里的相对路径 `fixtures/test-avatar.png`，不是按集合文件目录。
不在 `postman/` 目录下跑，文件就找不到 → 请求不带文件 → 后端 `MultipartException` → 5000。
**表象像"上传功能坏了"，实际是调用目录错了。**

**坑：`docker compose logs --since` 按本地时间解析**
我一开始传 UTC，统计窗口被放大 8 小时，"干净窗口"里混进了一大堆历史错误。
时间是这种"隐形参数"，错了不会报错，只会给你错误的结论。

**坑：`mvn` 默认用 JDK 11，报「无效目标发行版：17」**
本机 `JAVA_HOME` 指向 jdk-11，每次都得显式 `JAVA_HOME='D:\jdk17\jdk-17.0.20+8' mvn ...`。

### 1.3 本地阶段最重要的产出：5 层回归

最终固化成 5 层，全绿基线：

```
Newman 接口回归   123 请求 / 768 断言
落库校验          verify_db_redis.py   11/11
端到端冒烟        smoke_test.py        18/18
后端单测          mvn verify           204 测试
前端              vitest               单元 / 集成 / 回归三类
```

**这套基线后来救了很多次。** 因为它的存在，"我改的东西有没有碰坏别的"变成了一个可执行的问题，
而不是靠肉眼 review。

## 二、阶段二：首次上线（2026-10-17 凌晨）

### 2.1 第一个死结：算力包实例不能备案

原计划是「买域名 → 备案 → 上 HTTPS」。核实备案前提时撞上硬规定，阿里云帮助文档原文：

> **算力包仅支持创建按量付费实例，不支持 ICP 备案**，如有备案需求，请前往 ECS 包年包月购买。

而备案对服务器的要求是「包年包月、且购买时长 > 3 个月」。
我们用的是学生算力包抵扣的按量付费实例 ⇒ **拿不到备案服务码，做不了 ICP 备案。**

第二重障碍更麻烦：**个人备案对网站内容有严格限制**。
名称严禁含「商城/购物/交易/平台」等词，且只允许非经营性内容。
而本项目首页就是商品、价格、秒杀、支付入口 —— 个人备案大概率被驳回。

三条路摆出来：

| 路 | 做法 | 成本 | 结果 |
|---|---|---|---|
| A | 不备案，继续用 `http://IP:8080` | 0 | 能用，但不像"上线" |
| B | 买 99 元包年实例 + 域名 → 转备案 | ~110 元 | 要削掉电商属性才能过 |
| C | **换境外/香港服务器（不需要备案）+ 域名** | 0（用现有算力包额度） | **域名 + HTTPS** |

最后选了 C 的变体：**算力包支持「美国（弗吉尼亚）」地域，境外不需要 ICP 备案**。
用现有额度，0 额外成本，代价是国内访问首屏 1~3 秒。

> 这里用户自己踩了一个坑：他第一次打开的是**普通自定义购买页**，选了
> 「包年包月 + 计算型 c9i ¥268/月」—— c9i 完全不在算力包可抵扣的 13 款规格里，
> 在那个页面点「立即购买」就是自费 268 元/月起。及时制止，换回算力包专用入口。

### 2.2 国内实例先跑通（后来释放）

先用国内一台 `8.155.131.145` 把整条链路跑通，01:12 外网验收全绿。
然后因为域名要走境外，把这台的数据库全量备份拉回本机
（`国内实例-final-backup-20261017-025231/`，6 个 `.sql.gz`），确认**订单数为 0**、上传目录为空后释放。

关于"停机省钱"这件事也说清楚：**按量付费实例停机仍然计费**，
只有「释放」才停计费；而「节省停机模式」会**释放固定公网 IP**，
配了域名的机器一旦停机，域名就断了。所以"要省钱只有释放"。

### 2.3 美国实例：ping 通、TCP 全超时

美国实例 `43.111.225.28`：**ping 262ms 通，但 TCP 22/80/443 全部超时。**
对照国内那台 22 和 8080 都正常，于是排除了"我这边的公网"。

排查走了两条弯路，都值得记：

**弯路一：安全组按地域隔离**
用户按我之前（错误的）说法"美国那台应该和国内同一个默认安全组"去加了 80 规则，
结果加到了 `sg-f8z3hrw9d0pzki8h9xwq`（**华北2 北京**），对美国实例毫无作用。
美国实例实际用的是 `sg-0x4b4t3i37jrtdoyp2u`（**美国弗吉尼亚**）。
⇒ **每个地域有各自的默认安全组，加规则必须先在地域切换器切到目标地域、
先确认实例实际所属的安全组 ID。**

**弯路二：`ufw default deny incoming` 之后 ICMP 仍然通**
看到"ping 通但 TCP 不通"，第一反应是安全组。实际安全组规则齐全。
真凶是实例内的 ufw —— 但 ufw 的 `before.rules` 里有 `icmp echo-request ACCEPT`，
所以 `default deny incoming` **只挡 TCP/UDP、不挡 ping**。这个组合极具迷惑性。

而且当时 `server-init.sh` 在 ufw 段被中断过，留下了「已启用 + 无放行 22」的死状态。
最后是让用户从**控制台的 VNC 远程连接**（走云平台通道，不经网络栈，不受 ufw 影响）
进去 `ufw disable` 才恢复。注意 Workbench 走 SSH，一样会失败。
VNC 里还有个细节：**终端不支持 Ctrl+V 粘贴**，按了会得到 `: command not found`，
所以给用户的命令必须极短、可手打。

**真凶（02:10 定位）**
VNC 里 `ss -tlnp` 证明：**sshd 一直在正常监听 0.0.0.0:22，服务端毫无问题。**
是我所在的沙箱到 `43.111.225.28` 的网络路径断了，而国内服务器到该 IP 完全可达。

**这条是整轮最贵的教训：判定"服务器故障"之前，必须先用第二个独立视角验证。**
有效手段：用已有 SSH 权限的另一台机器去测目标端口。

```bash
ssh 已有权限的机器 'timeout 12 bash -c "exec 3<>/dev/tcp/<目标IP>/<端口>"'
```

我因为没做这一步，让用户白折腾了：关 ufw、查安全组、重启实例。

**连带的第三个坑：自己把自己挡在跳板外面**
想用国内机器作 ProxyJump 跳板，报 `stdio forwarding failed` ——
因为**我自己写的加固脚本设了 `AllowTcpForwarding no`**。
临时改回 `yes` 才通。加固脚本要按"这台机器的实际用途"调整，不能一把梭。

给 `server-init.sh` 加的保险（本轮最重要的产物）：

```bash
if ufw show added | grep -qE 'allow .*22/tcp'; then
    ufw --force enable
else
    die "ufw 未成功写入 22/tcp 规则，已【放弃启用】防火墙（保持关闭，避免把远程锁死）"
fi
```

**宁可保持防火墙关闭（能进去修），也不带着不完整规则启用。**

### 2.4 美国实例部署完成（02:22）

源码 1.8M 经跳板上传 → `/opt/PeakFlow`（304 文件）→ 6 容器全 healthy → 冒烟 9/9。
从国内服务器（第三方视角）实测 `/healthz`、`/`、`/api/seckill/list` 全 200。

**gzip 生效**：主 JS `1,250,321 → 403,995 bytes`（省 68%）。
这个必须单独说 —— 生产 nginx 配置**漏了 gzip**（开发那份反而有），
而 nginx 默认只压缩 `text/html`，JS/CSS/JSON 全不压，它们才是大头。
在 328ms 的跨国链路上，首屏从 5~8 秒降到 1~2 秒。

还有一个隐蔽的：**打包前必须重新 `git archive`**。
曾因为 tarball 早于 gzip 修复，传上去的配置还是旧的（文件里明明有 gzip）。
核对手段：`tar -xzOf 包 ./deploy/nginx/peakflow-prod.conf | grep -c "^gzip"`。

## 三、阶段三：域名与 HTTPS（02:32 ~ 03:40）

### 3.1 买了域名不等于能解析：`client hold`

买了 `peakflow.top` 之后，`nslookup -type=NS` 在 Google DNS 和阿里 DNS 上**都是 NXDOMAIN**。
WHOIS 显示 `client hold`。

**根因**：阿里云对新注册的 `.top` 域名会先置 `clientHold`，
**待域名实名认证通过后才自动解除**。所以"买了 → 加 A 记录 → 立即生效"这个预期不成立。

### 3.2 模板实名 ≠ 域名实名

用户先完成了**信息模板实名**（模板 ID `25295106`），但域名仍被锁。
因为**模板只是一份可复用的身份资料**，必须显式**应用到域名**上才算完成实名。
最后是在「域名持有者信息修改（过户）」页用「快速过户」把已实名模板应用到域名，03:10 过户成功。

**判断实名是否生效的正确方法：看 NS 能否解析，不要看 WHOIS 的 `client hold`。**
`client hold` 会让域名在顶级域里没有 NS 委派 ⇒ 查 NS 返回 NXDOMAIN。
反之 NS 能查到 = 委派已建立。本次 WHOIS 页面仍显示 `client hold`（缓存滞后），但 NS 已经能解析了。

### 3.3 签证书 + 上线（03:40）

```
买域名 → 信息模板实名 → 把模板应用到域名 → NS 可解析 ⇒ client hold 解除
→ 加 A 记录 → 签 Let's Encrypt 证书 → 叠加 HTTPS 层
```

**域名环节的 4 个真 bug：**

**① `deploy.sh` 证书检查用裸 `[ -f ]`，明明签好却判定"没有证书"**
`/etc/letsencrypt/live` 默认是 `drwx------ root root`，非 root 的部署账号读不到 ⇒
不叠加 HTTPS 层 ⇒ **443 一直不通**。
修法：`cert_present()` 回退到 `sudo -n test -f`。
⚠️ **不要**用 `chmod 755 /etc/letsencrypt/live` 这个常见偏方 —— 那等于把 `privkey.pem` 暴露给本机所有用户。

**② nginx 报 unhealthy，部署中断，但站点其实完全正常**
镜像里 healthcheck 是 `wget http://127.0.0.1/healthz`；开 HTTPS 后 80 一律 **301 跳转**，
wget 默认**跟随跳转** ⇒ 容器内要解析域名走公网 hairpin ⇒ 失败。
修法：在 HTTPS 覆盖层里重定义 healthcheck，接受 `200|301|302`。
**健康检查要回答的是"nginx 还活着吗"，不是"业务接口通不通"。**

**③ HSTS 配了但不生效**
写在 TLS 模板的 **server 级**，而 `peakflow-locations.inc` 里凡是自己设过 `add_header`
的 location（`/assets/`、`= /index.html`）会**丢弃 server 级全部 add_header**。
修法：把 HSTS 挪进 `peakflow-security-headers.inc`，与其余 4 个头同层级。
（在 80 上多带该头无害 —— RFC 6797 §7.2 规定浏览器只在 HTTPS 上认。）

**④ `www` 子域 CAA 查询瞬时 SERVFAIL**
`www` 的 A 记录刚加不到 1 分钟，阿里云 DNS 集群间还没同步完，首次签证书失败。
等几分钟重试即成功，**不是配置问题**。诊断用 `dig CAA www.peakflow.top @8.8.8.8`。

**最终验收**：证书 `CN=peakflow.top`，SAN 含 `peakflow.top` + `www.peakflow.top`，有效期至 2027-01-14；
`/healthz`、`/`、`/login`、`/admin/login` 全 200；HTTP→HTTPS 301；**5/5 安全响应头**；
gzip 生效；16 并发登录 → 6×200 + 10×429（限流生效）。

### 4.2 第一轮：支付确认失败（05:00 前后）

**现象**：点「确认支付」报「网络异常 / JSON 格式不支持」。
**关键难点**：报错不在商城的 Vue 页面，而在 **MockPay 收银台页**（后端的一个静态 HTML）。

按用户给的 a~f 六步逐项排查：
URL/方法/头正常 → 请求体 GET 无 body → **后端返回合法 JSON**（实测 `stock=0, seckillStock=50`）→
无跨域/截断 → 无需 token → 有 try-catch 不是解析失败。

**根因**：`mock-pay-cashier.html:164` 写死 `fetch('/mock-pay/pay')` —— **根相对路径**。
生产收银台的地址是 `https://peakflow.top/api/mock-pay/cashier`（经 nginx `/api` 前缀暴露），
所以这个 fetch 实际打到 `https://peakflow.top/mock-pay/pay`，
而 nginx 没有这个 location ⇒ **405 HTML** ⇒ `r.json()` 解析失败 ⇒ 显示「网络异常」。

**为什么本地和回归测试全绿**：本地 `cashier-url` 是 `http://127.0.0.1:8080/mock-pay/cashier`
（根路径直挂），恰好能通；而 newman 的 mock-pay 用例都是**服务端直调**，不经过浏览器 fetch。

**修法**：改成**文档相对路径** `fetch('pay')` —— 浏览器按页面自身 URL 解析，
生产 `/api/mock-pay/pay`、本地 `/mock-pay/pay` **两个环境都对，零配置**。
另外加 `r.ok` 检查和非 JSON 响应的可读提示。

**还补了一个真正的测试**：`cashier-page.test.js` 直接读取后端那个 HTML、
取出内联 `<script>` 在 happy-dom 里**真实执行**，断言"接口地址必须是文档相对路径"。
这个测试以后能永久拦住同类问题。

**这轮上线后出现了一个事故（我自己造成的）**：
手动重建 nginx 时只写了 `-f docker-compose.yml -f docker-compose.prod.yml`，
**漏了 `-f docker-compose.https.yml`** ⇒ 新容器丢了 443 端口映射和证书挂载 ⇒ **全站 HTTPS 中断约 2 分钟**。
更坑的是：容器 healthcheck 走的是 80 的 `/healthz`，**照样显示 healthy**。
⇒ **「healthy」不等于「对外服务完整」**。
恢复：用完整三文件栈 `up -d nginx`。
从此定规矩：**重建生产 nginx 永远走 deploy.sh**，不要手拼短栈 compose；
验证必须从外网视角（`curl -sI https://域名`），容器内 healthy 不算数。

### 4.3 第二轮：秒杀详情等 4 个问题（10:20 ~ 11:00）

用户报了 4 个问题，全部先定位到行号再改。

**① 秒杀商品有库存，详情页却显示"已售完"、库存 0，但点抢购又能成功**
实测 `/api/product/detail/5` 返回：`stock=0, seckillStock=50, isSeckill=1`。
**后端有两个独立库存字段**（普通库存 / 秒杀库存，秒杀商品 stock 恒为 0），
而详情页的展示、售罄提示、进度条**全读 `stock`**，只有抢购校验读 `seckillStock`。
⇒ 同一个页面两套口径，自相矛盾。

修法：抽 `availableStock` / `stockLabel` / `isSeckillProduct` 三个计算属性，
展示、售罄提示、抢购校验、进度条统一走同一口径。普通商品逻辑不变。

**② 登录日志明明成功，状态列全是"失败"**
`login_log` 表只有 `id/user_id/username/ip/login_time/remark` —— **根本没有 status 字段**。
前端按 `row.status === 1` 判断，`undefined === 1` 恒为 false ⇒ 一律显示"失败"。
修法：状态列改读 `remark`（日志本就只在登录成功后写入），并删掉永远为空的「登录地点/设备」两列。
**没有加 DB 字段**（避免生产 ALTER）。

**这里发现了一个更值得警惕的东西**：`test/handlers.js` 的测试桩**臆造了 `status/location/device`
三个后端根本不存在的字段** —— 这正是这个 bug 长期测不出来的原因。
桩比实现"更美好"，测试就成了装饰。

**③ 协议链接点了没反应**：`<a>` 没有任何事件。新增 `constants/agreements.js` 存两份协议全文 + 弹窗。

**④ 秒杀不允许加购/调数量**：这是正确的业务约束（后端下单固定 1 件、唯一索引限购），
但 UI 上只表现为"输入框神秘地不能调"。改成明示「秒杀限购 1 件」，把限制讲清楚。

**这轮我自己引入了一个回归**：把协议 `<a>` 放进了 `el-checkbox` 的 label 内，
并用 `@click.prevent.stop` 阻止冒泡 ⇒ **勾选框完全勾不上 ⇒ 用户无法登录**。
单测没发现，是**生产实测**才暴露的。修法：链接移出 label。
补了一条"真实点击 checkbox input 必须勾上"的回归测试。
教训：**交互元素互相嵌套时，必须用真实点击验证，不能只测 vm 状态。**

**这轮还有一个隐藏的后端缺陷**（回归跑出来的）：
用户取消秒杀订单后，DB 的限购位已按设计释放（允许重新参与），
但 Redis 的购买权门闩 `seckill:order:success:{userId}:{productId}`（24h TTL）
**只在失败路径释放，取消路径漏了** ⇒ 用户取消后再抢，被「您已参与过该秒杀活动」拦 24 小时。
修法：`rollbackStock` 的秒杀分支在回补 DB + Redis 库存的同时调用 `releasePurchaseGate`，并补单测。
注意：**修复前产生的门闩不会自动清**，得手工 `DEL`（本次清了一条）。

### 4.4 第三轮：购物车后端缺陷（11:40 ~ 12:50）

这轮是"发现问题的方式"最有价值的一次：**我是用接口直接打生产打出来的**，
不是看代码猜的。

**① 秒杀商品能经 API 加入购物车**
前端隐藏了「加入购物车」按钮，但 `CartServiceImpl#addToCart` **完全没校验**。
更糟的是：秒杀商品 `stock=0`，会先命中库存校验，返回「商品库存不足」——
用户以为是没货，实际是渠道不对。
修法：库存校验**之前**按 `isSeckill` 拦截，返回「秒杀商品仅支持秒杀通道购买，不可加入购物车」。
**这条最普适：前端隐藏入口 ≠ 业务规则，规则必须在服务端。**

**② 加购失败留下 `quantity=0` 幽灵条目**
实测现场：`POST /cart/add?productId=5` 失败后，`/cart/list` 返回 `[{productId:5, quantity:0}]`。
根因：回滚用 `increment(-quantity)`，商品原本不在购物车时减回去会留下 `value=0` 的字段；
而列表清理条件是 `stock < quantity`，**对 0 不成立 ⇒ 永远清不掉**。
后果：购物车出现「0 件」行、**顶栏角标按条目数计数会虚增**。
修法：回滚区分「本次新增 → `HDEL`」与「累加失败 → 减回」；列表补 `quantity <= 0` 判失效
（顺带自愈历史脏数据）。

**这轮上线后，回归首跑有 3 项红**，排查后确认**全是测试脚本自身缺陷，产品行为正确**：

- 售后链路下单 `orderId=None`：后端对「同用户 + 同商品清单」有 MD5 幂等锁，
  脚本两处用了同样的清单 ⇒ 第二次被正确拒绝。实测验证：第 1 次 200，第 2 次 3005「订单重复提交」。
- 「必须出现 429」：取决于 nginx 漏桶 burst 是否刚被上一轮消耗，属于**时序相关的脆弱断言**。
  本轮分布 `{3005:15, 200:1}` —— 全部被限购拦下、零 5xx，保护是生效的，只是没走到限流层。
  改成断言真正该保证的语义：**高压下只可能成功或被保护机制拦下，绝不 5xx、绝不超卖**；
  429 降级为"仅观测"。

修完 **65/65 全绿**。

## 五、踩过的坑：按"价值"分级

我把 40 多个坑按"能省多少时间/避免多大损失"排序，最有价值的放前面。

### S 级：会直接误导你的判断（不看会走大弯路）

**S1. 判定"服务器故障"之前，先用第二个独立视角验证**
本次最贵的一课。沙箱到美国 IP 的路由瞬断，服务端完全正常（VNC 里 `ss -tlnp` 证明 sshd 在听），
但我被判成"被 ufw/安全组锁死"，让用户白关了防火墙、白查了安全组、白重启了实例。
**复用动作**：`ssh 有权限的另一台机器 'timeout 12 bash -c "exec 3<>/dev/tcp/IP/端口"'`

**S2. 本机有 HTTP 代理，会把外网测试结果污染成假象**
`http_proxy=http://127.0.0.1:xxxxx`。代理到不了的目标会**返回 502 Bad Gateway**（带 `Retry-After`）。
我曾以为"服务器 8080 返回 502"，差点去查 nginx 陈旧 DNS。
**规矩**：测外网一律 `curl --noproxy '*'`；见到莫名 502/403 先 `curl -v` 看有没有 `Uses proxy env variable`。
这个坑的 python 版是：`urllib` 也会走代理，而且**代理会剥掉 `Authorization` 头** ⇒ 接口全 401。
脚本里必须 `urllib.request.install_opener(build_opener(ProxyHandler({})))`。

**S3. 容器 `healthy` ≠ 对外服务完整**
重建 nginx 漏带 https 覆盖层，容器照样 healthy（healthcheck 走 80），但 443 没了。
**健康检查只回答它被定义的那个问题。** 验证服务必须"从用户所在的位置"验证。

**S4. 测试桩比实现"更美好"，测试就是装饰**
两处血案：登录日志桩臆造了 `status/location/device`（真 bug 长期测不出）；
购物车删除桩只回"成功"却不改数据（"删完就空"永远测不出来）。
**规矩**：写桩之前先 `curl` 一次真实响应，**照抄字段名与类型**。

**S5. 业务规则只做在 UI 层等于没做**
秒杀商品前端隐藏了加购按钮，后端却没校验。任何能直接调接口的客户端都能绕过去。
**凡"前端隐藏了入口"的功能，都要回头确认后端是否也拦了。**

**S6. `set -o pipefail` + `| head -c N` 会静默杀死整个脚本**
`head` 读够就退出 ⇒ 上游 `tr` 收 SIGPIPE 退出 141 ⇒ `set -e` 中断。
表现是**脚本一个字都不输出就死掉**，极难排查。
修法：`... | head -c "$n" || true` + **显式校验长度**。

### A 级：能省半天到一天

**A1. nginx 只在启动那一刻解析 upstream**
后端容器重建换 IP 后，nginx 仍连旧 IP ⇒ 超时 10s ⇒ **504，且后端日志里看不到该请求**。
极易误判成后端故障。⇒ **重建后端后必须 `restart nginx`**。

**A2. nginx `add_header` 就近覆盖**
location 里设了任何响应头（含 `expires`），server 级**所有** `add_header` 在该 location 全部失效。
HSTS 就是这么消失的。⇒ 安全头抽成片段，在每个自带头的 location 里重复 `include`。

**A3. `ufw default deny incoming` 之后 ICMP 仍通**
ufw 的 `before.rules` 放行 `icmp echo-request`，所以"ping 通但 TCP 不通"不等于"不是防火墙问题"。

**A4. 阿里云安全组按地域隔离**
每个地域有各自的默认安全组。加规则前必须先切地域、先确认实例实际所属的安全组 ID。

**A5. 域名 `client hold`：买了不等于能解析；模板实名 ≠ 域名实名**
判断实名是否生效**看 NS 能否解析**，不要看 WHOIS 的 `client hold`（页面缓存滞后）。

**A6. 证书文件用裸 `[ -f ]` 判定会失败**
`/etc/letsencrypt/live` 是 `700 root`，非 root 读不到。
**绝对不要** `chmod 755` 那个目录（等于泄露私钥），用 `sudo -n test -f` 只判存在。

**A7. newman 按"当前工作目录"解析 `src` 相对路径**
不在 `postman/` 下跑，上传用例就报 `not a multipart request`，看起来像上传功能坏了。

**A8. 前端隐藏的"根相对路径"在生产下会打到错误位置**
收银台 `fetch('/mock-pay/pay')` 在本地根路径直挂时能通，生产走 `/api` 前缀就 405。
**规矩**：静态页面里写接口路径，一律用**文档相对路径**或完整 URL，别用根相对路径。

**A9. scoped 样式特异性 0,2,0 压过全局单类 0,1,0**
移动端覆盖必须加 `!important`，否则改了没效果（详情页 420px 图片溢出就是这么来的）。
做法：所有 `!important` 都包在 `@media (max-width:768px)` 里，桌面端自然不受影响。

**A10. 本地跑 vitest 并行会静默丢测试文件**
多 worker 同时写系统临时目录，受限环境 `EPERM` ⇒ **整个测试文件被跳过**。
实测同一套用例总数在 176/164/158 之间漂移，**看着全绿其实少跑了文件**。
⇒ 本机必须 `--no-file-parallelism`；CI 不受影响。

**A11. 打包前必须重新 `git archive`，并核对包内内容**
曾因为 tarball 早于修复，传上去的还是旧配置（文件里明明改过）。
核对：`tar -xzOf 包 ./path/to/file | grep -c "关键词"`。

**A12. `agent-browser` 输出必须重定向到文件**
浏览器守护进程会**继承 stdout**，用管道永远等不到 EOF（表现为"卡死"，其实早就跑完了）。
另外 eval 的 JS **必须单行**（`json.dumps` 会把换行转成字面 `\n`，shell 双引号不转义 ⇒ 语法错误 ⇒ 读不到结果）。

### B 级：知道能少踩一次

- **B1** `MSYS_NO_PATHCONV=1` 是给 `docker exec -w /容器/路径` 用的，**对 git 是毒药**（`git -C /e/x` 会解析错）。
- **B2** `MSYS_NO_PATHCONV` 下路径别写 `/d/...`，否则会落到"当前盘根目录"（曾把 clone 落到 `E:\d\...`）。
- **B3** `.env` 同名键以**最后一条**为准 ⇒ 加键前先 `grep -oE '^[A-Z_]+=' .env.example | sort | uniq -d` 查重。
- **B4** `docker compose logs --since` **按本地时间解析**，传 UTC 会把窗口放大 8 小时、统计全错。
- **B5** `mysqldump` 会注入 `SET TIME_ZONE='+00:00'`，与应用 JDBC 的 `Asia/Shanghai` 差 8 小时。
- **B6** 秒杀时间窗不能写死日期，否则过期后秒杀列表全空 ⇒ 用 `DATE_SUB(NOW(), INTERVAL 1 HOUR)`。
- **B7** 单实例 Docker 里 MQ 的 named volume 属主不对会导致 broker **exit 253 且无日志**。
- **B8** healthcheck 写 `localhost` 会优先解析 IPv6 `::1`，而 nginx 只监 IPv4 ⇒ 永远 unhealthy。
- **B9** newman 容器内必须 `--env-var baseUrl=http://nginx/api`：环境文件默认的 `localhost:8080` 指的是 tester 自己。
- **B10** **按下单数量递增**：后端对"同用户 + 同商品清单"有 MD5 幂等锁，回归脚本重复下同样的单会被正确拒绝。
- **B11** 断言要避免时序依赖：`必须出现 429` 这类断言取决于漏桶状态，应该断言**语义**
  （零 5xx / 无超卖 / 只可能成功或被保护机制拦下），而不是某一个具体码。
- **B12** 从算力包创建的 ECS **不能 ICP 备案**；境外服务器不需要备案。
- **B13** 按量付费实例**停机仍计费**，只有释放才停；"节省停机"会**释放固定公网 IP**（域名会断）。
- **B14** 安全组默认不放行 8080：`ss` 显示监听 ✓、ufw 放行 ✓、`127.0.0.1` 200 ✓，但公网超时 ⇒ 就是安全组。
- **B15** `mysql` 客户端默认字符集不是 utf8mb4，含中文别名/数据的脚本要加 `--default-character-set=utf8mb4`。
- **B16** 自己写的加固脚本设 `AllowTcpForwarding no` 会让 ProxyJump 跳板失效。

## 六、从坑里提炼的 6 条规矩

这 6 条是这次真正的沉淀，比任何单个技能点都值钱。

**1. 先验证"我的观测本身是否可信"，再判断"系统是否有问题"。**
代理会伪造 502、缓存会让 WHOIS 滞后、并行测试会静默丢文件、`healthy` 只代表 80 通。
**观测工具本身也会骗人。**

**2. 判断故障必须至少两个独立视角。**
服务器自己 `curl 127.0.0.1` 通 + 外部 `curl 公网` 通 = 真通；
只有一侧通，先怀疑路径，不要先怀疑服务。

**3. 一切"契约"必须从真机取，不能从记忆取。**
字段名、错误码、状态枚举、接口前缀 —— 全部 `curl` 一次照抄。
桩数据造假是测试体系最致命的病。

**4. 业务规则写在服务端，UI 只是体验层。**
隐藏按钮不是权限，前端校验不是校验。所有"不允许"的操作，后端必须能独立拦住。

**5. 任何改动都要能退回去。**
每轮上线前备份 + 记录镜像 ID；`rollback_prod.sh` 一条命令回到任意提交。
**没有回滚方案的发布不叫发布，叫赌博。**

**6. 修完一个 bug，要问"为什么测试没抓到它"，并把这个缺口补上。**
支付 405 → 补了执行真实内联脚本的测试；登录日志 → 修了造假的桩；
秒杀库存 → 补了口径一致性测试；勾选框 → 补了真实点击测试。
**补不上缺口的修复，同一个 bug 会换个位置再来一次。**
